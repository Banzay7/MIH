# Грабер плейлистов

Грабер сам ищет публичные плейлисты M3U, понемногу проверяет их в фоне и добавляет в каталог только те потоки, которые реально играют. Работает в две ступени.

## 1. Поисковик (`discover`, каждые 5 мин)

За один запуск поисковик делает небольшой кусок работы. Поиск новых ссылок проходит кругами: в первые 60 дней круг повторяется раз в сутки, потом раз в месяц (`MIH_DISCOVERY_SEARCH_EVERY`). Внутри круга поисковик идёт понемногу: не больше 4 запросов к GitHub за запуск (с токеном 20), а когда круг пройден, до следующего не тратит ни одного.

**Сбор ссылок.** Ссылки на плейлисты берутся из трёх мест:

- **Сиды.** Известные бесплатные плейлисты из [каталога источников](sources/README.md) и репозитории, которые их публикуют (`iptv-org/iptv`, `Free-TV/IPTV` и другие), а также вьетнамский список IPTV Finder с free-codecs.com (почти целиком совпадает с iptv-org, но несколько потоков есть только там). Из сид-репозиториев берётся каждый файл `.m3u`/`.m3u8`, они пересматриваются в каждом круге.
- **GitHub.** Поиск репозиториев (`topic:iptv`, `topic:m3u`, `iptv m3u` и другие запросы, свежие первыми), затем в каждом найденном репозитории берутся до 40 файлов `.m3u`/`.m3u8`. С `MIH_GITHUB_TOKEN` дополнительно идёт поиск по коду: файлы с `#EXTINF`. Без токена GitHub даёт 60 запросов в час, грабер тратит не больше 4 за запуск, то есть до 48 в час; с токеном до 20.
- **Страницы и Telegram** из `MIH_DISCOVERY_FILE`: форумы, списки ссылок и публичные каналы Telegram (читается веб-версия `t.me/s/<канал>`, без аккаунта). Со страницы берутся ссылки на `.m3u`/`.m3u8` и на репозитории GitHub. Каждая страница читается один раз за круг.

**Выборочная проверка.** Поисковик берёт 5 найденных плейлистов (`MIH_DISCOVERY_SCOUT`), то есть примерно один в минуту, и для каждого:

1. Скачивает файл с теми же ограничениями, что при обычном импорте.
2. Отсеивает утечки (см. «Что грабер не берёт»).
3. Оставляет только потоки, которых ещё нет в каталоге.
4. Проверяет случайные 10 из них той же пробой, что и [проверка потоков](health.md).

Если сыграл хотя бы один поток, плейлист **живой** и уходит упаковщику.

Итог по плейлисту:

| Статус | Что значит |
|---|---|
| `new` | найден, ещё не проверен |
| `live` | в выборке есть рабочие потоки, ждёт упаковщика |
| `packed` | упакован в каталог |
| `dead` | не скачался или ни один поток из выборки не сыграл; повтор через неделю, после 3 неудач плейлист бросается |
| `known` | все его потоки уже есть в каталоге |
| `duplicate` | точная копия уже найденного (форк) |
| `rejected` | не плейлист, пустой, больше 20 000 записей, или в основном утечки и DRM |
| `retired` | был упакован, но все его потоки умерли; источник выключен |

## 2. Упаковщик (`pack`, каждые 15 мин)

Упаковщик берёт один живой плейлист (с лучшей долей рабочих в выборке) и проверяет его новые потоки порциями по 60 за запуск (`MIH_DISCOVERY_PACK_BATCH`). Большой плейлист проверяется за несколько запусков, прогресс сохраняется.

После каждой порции:

- Рабочие потоки сразу импортируются как отдельный источник `auto: <хост>/<путь>`, через обычный импорт со склейкой каналов и справочником. Каналы из большого плейлиста появляются с первого запуска, а не после проверки всего плейлиста. Когда проверено всё, плейлист получает статус `packed`. Проверка упаковщика засчитывается потокам как первая, поэтому они сразу попадают в валидные списки.
- Мёртвые потоки в каталог не попадают совсем. Исключение — каналы своей страны, см. ниже.
- Дальше потоки ведёт обычная [проверка потоков](health.md): первые сутки раз в час (пробный период: стабильность, разрешение, время старта), потом раз в неделю.

Раз в неделю упакованный плейлист перечитывается: новые потоки проходят тот же путь. Если все его потоки умерли, источник выключается (`retired`).

Пока упаковщика ждут 50 живых плейлистов, поисковик только собирает ссылки и не проверяет новые. Результат проверки хранится по адресу потока неделю, поэтому одинаковые потоки в форках и копиях не проверяются повторно. Упаковщик встаёт на паузу, когда в найденных источниках набралось `MIH_DISCOVERY_MAX_STREAMS` потоков (по умолчанию 30 000), чтобы база не разрасталась без присмотра.

## Каналы своей страны (геоблок)

Многие каналы открываются только из своей страны: сервер за границей получает HTTP 403 или не получает ответа, а дома тот же поток играет. Если задана `MIH_HOME_COUNTRY` (например, `vn`), упаковщик берёт такие потоки в каталог, даже когда с сервера они не открылись. Условия:

- страна в `tvg-id` совпадает с домашней (`VTV1.vn`, `HTV7.vn@SD`);
- проверка сорвалась так, как срывается геоблок: HTTP 403 или 451, нет ответа, или в названии стоит метка `[Geo-blocked]` (Ⓖ).

Такой поток попадает в каталог с причиной `blocked_by_geo`. В списках он идёт как недоступный по стране, пока телевизор дома его не запустит. После отчёта телевизора о запуске поток считается рабочим, и неудачные проверки с сервера 72 часа ему не засчитываются (подробнее в [проверке потоков](health.md)). Если дома его так и не запустили, через 3 дня неудач он уходит в карантин, как любой другой.

Плейлист, в выборке которого есть такие потоки, тоже считается живым.

## Что грабер не берёт

- **Подписки IPTV-провайдеров.** Ссылки с логином и паролем: `get.php?username=…`, `/live/<логин>/<пароль>/<id>`, параметры `username`, `password`, `user:pass@`.
- **Потоки с DRM**: `#KODIPROP` с ключом лицензии или DRM в манифесте.
- **Мультикаст** (`udp://`, `rtp://`): работает только в сети провайдера.
- **Хосты из `deny_hosts`.**

Если таких записей в плейлисте половина или больше, отклоняется весь плейлист. Ссылка `url-tvg` из найденных плейлистов не подключается: для найденных каналов хватает уже подключённых гидов, которые сопоставляют их по `tvg-id` и названию.

Каталог берёт только открыто опубликованные бесплатные каналы. По жалобе правообладателя хост добавляется в `deny_hosts`, а источник удаляется.

## Настройка

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MIH_EVERY_DISCOVER`, `MIH_EVERY_PACK` | `5m`, `15m` | Как часто работают поисковик и упаковщик; `off` выключает |
| `MIH_DISCOVERY_SEARCH_EVERY` | `auto` | Как часто начинать новый круг поиска ссылок: `auto` — ежедневно первые 60 дней, потом раз в месяц; или явно `1d`, `30d` |
| `MIH_DISCOVERY_SCOUT` | `5` | Сколько плейлистов поисковик проверяет за запуск |
| `MIH_DISCOVERY_PACK_BATCH` | `60` | Сколько потоков упаковщик проверяет за запуск |
| `MIH_DISCOVERY_MAX_STREAMS` | `30000` | Предел потоков в найденных источниках |
| `MIH_GITHUB_TOKEN` | — | Любой токен GitHub без прав; включает поиск по коду и поднимает лимит запросов |
| `MIH_DISCOVERY_FILE` | — | JSON со своими местами поиска (ниже) |
| `MIH_HOME_COUNTRY` | — | Страна, где стоят телевизоры (`vn`, `ru`): её каналы с геоблоком берутся в каталог на проверку домом |

Пример `MIH_DISCOVERY_FILE` (все ключи необязательны):

```json
{
  "playlists": ["https://example.org/free.m3u"],
  "repos": ["owner/repo"],
  "pages": ["https://forum.example.org/topic/123"],
  "telegram": ["channel_name"],
  "deny_hosts": ["paid-provider.example"]
}
```

## Свой плейлист

Свой плейлист (например, подписку, где ключ зашит в адрес) грабер не ищет и фильтром утечек не проверяет. Его подключают как обычный источник, адрес хранится только в базе:

```
mih add-source "мой плейлист" "<адрес плейлиста>"
```

Команда сразу импортирует плейлист и печатает итог без адреса. Дальше он обновляется задачей `sources`, как любой источник. Порталы Stalker/Ministra (адрес `.../api/v1/` плюс ключ или MAC) пока не поддерживаются.

## Где смотреть

- Экран **Статус** (блок «Грабер плейлистов»), `GET /api/v1/status` → `discovery`.
- Строка «Грабер» в ежедневной сводке.
- `mih discovery`: итоги; `mih discovery --status live`: список плейлистов в нужном статусе.
- `mih run-job discover` / `mih run-job pack`: запуск вне очереди.

Запуски без новостей в ленту не пишутся. Найденные живые плейлисты и упаковки попадают в ленту как рутинные события, без пушей.
