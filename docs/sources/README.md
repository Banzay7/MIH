# Каталог источников каналов и EPG (обзор по миру)

Статус: исследование, 26.10.2026 (дополнено плейлистами в тот же день). Код импорта EPG этот документ не меняет.
Машиночитаемая версия: [`catalog.yaml`](catalog.yaml).

## 1. Зачем

MIRTVONLINE работает по принципу BYOC: пользователь приносит свои плейлисты, мы потоки не поставляем и не рекомендуем. Но каталогу нужны **метаданные** (кто такой канал, страна, язык, логотип) и **программа передач** (EPG/XMLTV). Этот документ отвечает на вопросы:

- что в мире реально доступно по странам и языкам;
- насколько это свежо, стабильно и на каких условиях;
- как сделать источники выбираемыми пользователем и как помечать «серые» (пропадают и появляются).

## 2. Главные выводы

1. **Лучший EPG почти всегда у самого пользователя.** У IPTV-провайдера обычно есть свой XMLTV (Xtream Codes `xmltv.php`, ссылка `url-tvg` в заголовке M3U), у владельца тюнера есть EIT из эфира (tvheadend, HDHomeRun). ID в таком EPG уже совпадают с плейлистом. Это источник №1, и его надо брать автоматически из `url-tvg`.
2. **Публичных агрегаторов с глобальным покрытием три:** epgshare01, epg.pw, open-epg. Все бесплатные, все без лицензии на данные, все обновляются примерно раз в сутки, горизонт 2–4 дня. Используются только как «запасной» EPG по выбору пользователя.
3. **iptv-org больше не публикует готовые guide-файлы** (адреса `iptv-org.github.io/epg/guides/...` отдают 404 с 2023). Остались справочник каналов (CC0) и граббер (Unlicense, ~250 сайтов, 248 рабочих). Граббер можно запускать у себя, это единственный путь к EPG «из первоисточника» для многих стран, включая Вьетнам (`xem.kplus.vn`).
4. **Единственный легальный платный вариант с понятными условиями** для США/Канады и ряда других стран — Schedules Direct ($35/год, данные Gracenote, только для физлиц и одобренных приложений). Встраивать нельзя, но можно поддержать как источник, если пользователь вводит свой аккаунт и MIH попадёт в список Approved Applications.
5. **Русскоязычный EPG** в основном держится на сайтах-агрегаторах и IPTV-провайдерах (iptvx.one, teleguide.info, epg.it999.ru и др.). Решение владельца (26.10.2026): в каталог попадают все, с пометками; EPG, привязанные к IPTV-сервисам, помечены `tied_to_stream_service`.
6. **Нестабильность — норма.** Файлы переименовываются (epgshare01 сменил US1→US2, CA1→CA2, и все channel ID поменялись), бывают «пустые оболочки» (файл Пакистана 310 байт), бывают «замёрзшие» файлы (Саудовская Аравия не менялась с августа 2024, но выглядит живой). Поэтому статус источника нельзя задать один раз, его надо измерять.
7. **Время.** Почти все агрегаторы пишут UTC (`+0000`), русские провайдерские — Москва (`+0300`). Импорт обязан хранить UTC и исходное смещение (уже в спеке, раздел 19).
8. **Публичные плейлисты — большой пласт метаданных.** iptv-org, Free-TV, региональные списки (Вьетнам, Испания, Германия, Италия, Китай) и FAST-плейлисты несут tvg-id, логотипы, группы и ссылку на EPG в заголовке. Решение владельца: включаем их в каталог как `m3u_playlist` с пометкой об уровне метаданных (`rich` / `partial` / `none`). Подробности в §8.1.

|---|---|---|---|

| `tuner_eit` | EPG из эфира/спутника | tvheadend XMLTV export, HDHomeRun | Пользователь |

| `licensed_api` | Платные данные по подписке | Schedules Direct | Пользователь со своим аккаунтом |
| `channel_db` | Справочник каналов (без EPG) | iptv-org database, Wikidata | Встроено (метаданные) |

## 6. Реестр источников: модель

### 6.1. Два слоя

- **Каталог** (`catalog.yaml`, поставляется с продуктом и обновляется rule-pack'ом): описание известных источников — тип, шаблон URL, страны, языки, лицензия, ожидаемый горизонт, схема ID. **Ни один источник не включён по умолчанию.**
- **Инсталляция** (таблица `sources` пользователя): что пользователь выбрал из каталога или добавил сам, плюс измеренное здоровье.

Онбординг: пользователь выбрал страну и язык → MIH предлагает подходящие записи каталога галочками, с бейджем статуса и строкой про условия использования. `provider_epg` из `url-tvg` подхватывается сам и стоит первым.

### 6.2. Статусы

| Статус | Цвет | Значение | Поведение |
|---|---|---|---|
| `ok` | зелёный | Отвечает, файл свежий, есть программы | Обычный приоритет |
| `grey` | серый | Нестабилен: пропадает и появляется, переименовывается, бывает пустым или замёрзшим | Используется, но с пониженным приоритетом при маппинге; при сбое держим последний хороший снапшот; бейдж в UI |
| `down` | красный | Сейчас недоступен или отдаёт мусор | Не обновляется, последний хороший снапшот живёт до истечения программ; ретраи с backoff |
| `retired` | — | Пропал надолго (≥ 30 дней) или источник закрылся | Скрыт из выбора, у пользователя остаётся с пометкой |

`grey` — это не «плохой», а «ненадёжный». Источник становится серым, если за последние 14 дней выполнено хотя бы одно:

- ≥ 2 переходов `ok ↔ down` (мигает);
- файл по адресу исчез, а похожий появился под другим именем (переименование);
- «пустая оболочка»: размер или число программ упало более чем на 80% к медиане за 7 дней, либо доля каналов без программ > 50%;
- «замёрз»: `Last-Modified`/хэш не менялся > 48 ч или последняя программа заканчивается раньше чем через 12 ч;
- более 30% каналов сменили ID между снапшотами.

Обратно в `ok` — 7 дней подряд без признаков. В `retired` — 30 дней подряд `down`. Статус в каталоге (`status_hint`) — это только стартовая подсказка из исследования; реальный статус всегда считается по замерам инсталляции.

Позже, в облачном rule-pack'е, можно агрегировать анонимные замеры многих инсталляций и обновлять `status_hint` (opt-in, без URL пользователя, только ID записи каталога и итог пробы).

### 6.3. Приоритет при маппинге EPG

1. `provider_epg` (ID совпадают с плейлистом);
2. `tuner_eit`, `licensed_api`;
3. `grabber` с сайта вещателя;
4. `xmltv_aggregator` / `xmltv_fast` со статусом `ok`;
5. то же со статусом `grey`.

Внутри уровня — ручной приоритет пользователя. Это ложится на поле `priority` таблицы `sources` из спеки (раздел 15) и правило «не назначать по одному похожему имени».

### 6.4. Проба здоровья (предложение для EPG-треда, не реализовано)

Отдельный цикл, по умолчанию раз в 6 ч для выбранных источников:

1. Условный GET (`ETag`/`If-Modified-Since`), лимит размера, распаковка gz потоком.
2. Потоковый парсинг без загрузки в память: число `<channel>`, число `<programme>`, min/max времени, доля каналов без программ, выборка ID.
3. Запись в `source_probes (source_id, at, http_status, bytes, content_hash, channels, programmes, horizon_end, empty_channel_ratio, error)`.
4. Пересчёт статуса по правилам 6.2, событие `source.status_changed`.

Дополнения к таблице `sources` из спеки: `catalog_id`, `status`, `status_since`, `last_ok_at`, `last_probe_at`, `terms_ack_at` (пользователь подтвердил условия).

## 7. Условия использования и что мы поставляем

| Источник | Лицензия данных | Можно ли встроить в каталог |
|---|---|---|
| iptv-org database | CC0 | Да, как справочник (уже решено, D-04) |
| iptv-org/epg (граббер) | Unlicense (код); данные — сайтов вещателей | Да, как инструмент; пользователь запускает сам |
| Wikidata | CC0 | Да, как дополнительный справочник (логотипы, сети, страны) |
| globetvapp/epg | GPL-3.0 (репозиторий) | Да, ссылкой; права на сами программы не ясны |
| epgshare01, epg.pw, open-epg | Не опубликована; epg.pw — «только для тестирования» | Да, только как ссылка с пометкой «личное использование, условия источника» и подтверждением пользователя |
| i.mjh.nz | Не опубликована | То же |
| Schedules Direct | Лицензия Gracenote, только физлица, только одобренные приложения | Только «принеси свой аккаунт»; нужно попасть в Approved Applications |
| RU-агрегаторы (iptvx.one, teleguide.info, programtv.ru) | Нет | Да, серые, с пометкой «личное использование» |
| Провайдерские RU EPG (it999/edem, ottclub, shara-tv и т.п.) | Нет; связаны с IPTV-сервисами | Да, с пометкой «связан с IPTV-сервисом» |
| Публичные плейлисты (`m3u_playlist`) | Разные: CC0 (iptv-org), MIT, Apache + условия сайта, чаще нет | Да, с пометкой «содержит потоки» и уровнем метаданных; импорт по умолчанию «только метаданные» |

EPG и плейлисты скачивает инсталляция пользователя, мы ничего не перераспространяем. Каталог содержит описание и URL. Для облачного Pro-сервиса (если появится) источники без лицензии использовать нельзя.

Изменение относительно спеки v0.3 (раздел 6, D-04): раньше каталог не упоминал плейлисты с потоками. Теперь они есть в каталоге как источники метаданных; потоки из них попадают в каталог пользователя только если он сам включил режим `full` для этого источника.

| Источник | Что даёт | Лицензия | Роль |
|---|---|---|---|
| iptv-org database / API | Десятки тысяч каналов: страна, сеть, владельцы, категории, фиды, языки, таймзоны, логотипы, связь с guide-сайтами (`guides.json`), блоклист | CC0 | Основной справочник идентичности |
| Wikidata | Сети, владельцы, страны, логотипы, сайты, ID в соцсетях | CC0 | Дополнение, особенно для неанглоязычных названий |

### 8.1. Публичные плейлисты как источник метаданных

Режимы импорта источника `m3u_playlist`:

- `metadata_only` (по умолчанию): берём каналы, tvg-id, логотипы, группы, страну и язык, ссылку на EPG из заголовка. Потоки не создаются. Это обогащает справочник и сопоставление каналов из плейлистов самого пользователя.
- `full` (включает пользователь): плейлист становится обычным источником потоков, как любой URL, который пользователь добавил сам. Дальше работают проверка здоровья и карантин.

Пометка в UI берётся из `metadata_level`: `rich` — «есть метаданные», `partial` — «метаданные частично», `none` — «не содержит метаданных, только потоки». Плейлисты-производные (`derived_from`) почти не добавляют новых сведений, при импорте их записи сливаются с исходным списком.
