# Статус и уведомления

MIRTVONLINE сам рассказывает, что он делает. Есть три слоя:

1. **Лента событий** в базе. Работает всегда, без настройки. Её показывает экран «Статус» веб-интерфейса, `GET /api/v1/status`, `GET /api/v1/events` и `mih status`.
2. **Пуши через [ntfy](https://ntfy.sh)** на телефон или компьютер. Включаются одной переменной `MIH_NTFY_URL`.
3. **Ежедневная сводка** в `MIH_DIGEST_AT`: состояние каталога, что сделано за сутки, проблемы, передачи по вашим темам на сутки вперёд и план.
4. **Оповещения по темам**: пуш незадолго до начала передачи на тему, за которой вы следите, со ссылкой на запуск (см. ниже).

## Что делает планировщик

`mih serve` запускает встроенный планировщик (`MIH_SCHEDULER=0` выключает его). Задачи идут по одной, без параллельных запусков одной задачи:

| Задача | Имя | По умолчанию | Что делает |
|---|---|---|---|
| Обновление плейлистов | `sources` | каждые 6 ч | скачивает каждый источник с URL и импортирует его (с проверками размера, как при ручном импорте) |
| Обновление телепрограммы | `epg` | каждые 12 ч | то же для источников EPG с URL |
| Проверка потоков | `health` | каждые 10 мин | проверяет потоки, которым пора по [политике](health.md) |
| Оповещения по темам | `alerts` | каждые 5 мин | ищет в программе передачи по темам, которые начнутся в ближайшие `MIH_ALERT_LEAD`, и присылает пуш; запуск без новостей в ленту не пишется |
| Поисковик плейлистов | `discover` | каждые 30 мин | ищет новые публичные плейлисты и проверяет выборку их потоков, см. [грабер](discovery.md) |
| Упаковщик плейлистов | `pack` | каждые 15 мин | проверяет все новые потоки живого плейлиста порциями и добавляет рабочие в каталог |
| Сводка за сутки | `digest` | 09:00 по `MIH_TIMEZONE` | присылает сводку |

После старта задачи с интервалом ждут 2 минуты. Следующий запуск считается от конца предыдущего. Перезапуск сервиса план не сдвигает, а прерванный перезапуском запуск попадает в ленту предупреждением.

Любую задачу можно запустить сразу: кнопка «Запустить» на экране «Статус», `POST /api/v1/jobs/{имя}/run` или `mih run-job <имя>`. Результат запуска по требованию приходит пушем всегда.

## Уровни событий

| Уровень | Примеры | Пуш |
|---|---|---|
| `routine` | плейлист без изменений, плановая проверка потоков | нет, только лента и сводка |
| `info` | запуск и остановка сервиса, новые или пропавшие каналы, импорт и экспорт вручную, сводка | да, при `MIH_NOTIFY_LEVEL=info` |
| `warning` | источник отклонён или недоступен, у сервера нет интернета, задача прервана перезапуском | да, если уровень не `error` |
| `error` | все источники задачи недоступны, задача упала | да |

Одинаковое предупреждение одной задачи приходит не чаще раза в 6 часов, остальные повторы видны только в ленте. Падение сервиса целиком сервис сам сообщить не может: признак — отсутствие утренней сводки.

## Настройка ntfy

1. Установите приложение ntfy (Android: Google Play или F-Droid, iPhone: App Store) или откройте https://ntfy.sh/app в браузере.
2. Придумайте длинное случайное имя топика, например `openssl rand -hex 12`. Имя топика работает как пароль: кто его знает, тот читает пуши. На собственном сервере ntfy можно закрыть топик токеном (`MIH_NTFY_TOKEN`).
3. В приложении подпишитесь на этот топик.
4. Укажите `MIH_NTFY_URL=https://ntfy.sh/<топик>` (или адрес своего сервера) и перезапустите сервис.
5. Проверьте: `mih notify-test` или кнопка «Отправить тестовый пуш» на экране «Статус».

`MIH_LANG=ru` переводит тексты пушей и ленты на русский. `MIH_PUBLIC_URL` (адрес веб-интерфейса) добавляет к пушу ссылку на экран «Статус».

В ответах API адрес и топик ntfy не показываются, только то, что канал настроен.

## Оповещения по темам

Тема — слово или фраза: «футбол», «формула 1», «роботы». Добавить: вкладка «Избранное» → блок «Темы» → поле ввода → **Следить**, или кнопка «🔔 Следить за темой» под результатами поиска, или `POST /api/v1/profiles/default/topics`. Передача в избранном (★) тоже считается темой: о каждом её показе придёт пуш.

Как ищется: в названии, подзаголовке и жанре передачи, с начала слова, без учёта регистра, ё/е и диакритики («футбол» найдёт «Футбольный матч», но не «Суперфутболист»). Так же отбирает передачи режим `MIH_EPG_SCOPE=tracked`, поэтому для каналов вне списков программа хранится как раз по этим темам; новая тема начинает работать для них со следующего обновления программы.

Когда приходит пуш: задача `alerts` раз в `MIH_EVERY_ALERTS` смотрит передачи, которые начнутся в ближайшие `MIH_ALERT_LEAD` (по умолчанию 15 минут) или начались не больше 5 минут назад. Только каналы, у которых есть рабочий поток. Каждый показ объявляется один раз; одна передача на нескольких каналах в одно время — один пуш с названиями каналов; серия подряд на том же канале в пределах 3 часов — один пуш. Больше 5 совпадений за раз — пять пушей и шестой со списком остальных. Оповещения приходят при любом `MIH_NOTIFY_LEVEL`: вы сами попросили о них.

Что открывает нажатие (`MIH_ALERT_LINK`):

| Значение | Ссылка | Когда подходит |
|---|---|---|
| `play` | `MIH_PUBLIC_URL/play/<канал>?key=…`: сервис в момент нажатия выбирает лучший рабочий поток и перенаправляет на него; `…/play/<канал>.m3u?key=…` отдаёт плейлист из одного канала с нужными заголовками | сервис доступен с телефона по `MIH_PUBLIC_URL` |
| `stream` | сам адрес потока | сервис закрыт от интернета; адрес потока уходит в ntfy, поэтому для подписочных плейлистов с токеном в адресе лучше `play` или `none` |
| `none` | без ссылки | |
| `auto` (по умолчанию) | `play`, если задан `MIH_PUBLIC_URL`, иначе `stream` | |

Ключ `key` открывает только этот канал и не даёт доступа к API. Поток, которому нужны особые заголовки (User-Agent, Referer), по прямой ссылке не откроется, поэтому в режиме `stream` берётся поток без них.

Что будет в ближайшие сутки: блок «Скоро по вашим темам» во вкладке «Избранное» или `GET /api/v1/profiles/default/alerts/upcoming?hours=24`. Утренняя сводка тоже перечисляет эти передачи.
