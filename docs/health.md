# Проверка живости потоков

Реализация раздела 17 спецификации. Код: `src/mih/health/`.

## Состояния

| Статус | Когда |
|---|---|
| `unverified` | поток импортирован, ещё ни разу не проверялся |
| `new` | проверялся, но ни разу не заработал |
| `active` | последняя засчитанная проверка или запуск на устройстве прошли успешно |
| `suspect` | ≥ 3 неудачи подряд минимум в 2 разных часовых окнах |
| `quarantine` | поток в `suspect` и падает ≥ 7 суток подряд |
| `archived` | ≥ 30 суток в карантине; архивируется только поток, канал остаётся |

Любой засчитанный успех из любого состояния, включая `archived`, сразу возвращает поток в `active`. Единичная неудача только записывается и статус не меняет.

Фид считается воспроизводимым, если у него есть хотя бы один поток в `active` без причины недоступности (`GET /api/v1/channels/{id}/availability`, там же лучший поток для запуска).

## Причины недоступности

Отдельно от статуса: `drm_unsupported` (Widevine/FairPlay/PlayReady, `SAMPLE-AES`, `ContentProtection` в DASH), `authentication_required` (HTTP 401), `blocked_by_geo` (HTTP 451). Поток с такой причиной не считается мёртвым, статус не портится. Обычное шифрование `AES-128` причиной не считается: его играет любой плеер. Повторный импорт плейлиста эти причины не сбрасывает; сбрасывает их только успешная проверка.

## Как проверяется поток

1. HTTP-запрос с заголовками из плейлиста (`User-Agent`, `Referer`), редиректы вручную, каждый адрес проходит ту же защиту от SSRF, что и загрузка плейлистов.
2. HLS: из мастер-плейлиста берётся самый лёгкий вариант, из медиаплейлиста самый свежий сегмент, из сегмента читается не больше 64 КБ (`Range`).
3. DASH: пока проверяется только манифест, без сегмента.
4. TS и прочие прямые потоки: достаточно получить первые байты.

Поток не скачивается целиком, ключи расшифровки не запрашиваются, DRM и авторизация не обходятся. В базе и ответах API адресов нет.

## Что не считается смертью потока

Каждая проверка записывается в `stream_observations`, но часть из них помечена `counted = 0` и на статус не влияет:

- **нет сети у самой проверки**: перед запуском проверяются адреса из `MIH_HEALTH_CANARY_URLS`; если ни один не ответил, запуск ничего не оценивает (`vantage_offline`);
- **сбой сети в целом**: если ≥ 80% из ≥ 10 проверок упали на уровне сети (DNS, соединение, таймаут);
- **сбой источника**: если все ≥ 3 проверенных потока одного плейлиста упали разом, это провайдер или истёкшая подписка, а не потоки (`source_outages` в отчёте);
- **HTTP 429**: ограничение частоты запросов;
- **адрес из локальной сети**, если проверка стоит на удалённом сервере и `MIH_ALLOW_PRIVATE_SOURCES` выключен;
- **расхождение с устройством**, см. ниже.

## Сервер и телевизор

MIH работает на удалённом сервере, а смотрят дома, поэтому сервер видит сеть иначе: другая страна, другой провайдер, другие блокировки. Решающим считается реальный запуск на устройстве:

```
POST /api/v1/streams/{id}/playback  {"result": "started" | "failed", "startup_ms": 900}
```

- `started` сразу переводит поток в `active`;
- если устройство успешно играло поток в последние 72 часа, неудачи серверной проверки записываются, но не засчитываются;
- если устройство в последние 72 часа не смогло его запустить, успех серверной проверки поток не «оживляет».

## Расписание

Каждая проверка назначает следующую: `active` через сутки, `new` через 6 часов, `suspect` через 3 часа, `quarantine` через сутки, `archived` раз в неделю, `unverified` сразу. После неудачи поток перепроверяется через час, чтобы отличить кратковременный сбой от падения. Потоки, которых больше нет в плейлисте (`source_absent`), и потоки отключённых источников не проверяются.

Одновременно идёт не больше `MIH_HEALTH_CONCURRENCY` проверок и не больше `MIH_HEALTH_PER_SOURCE` (по умолчанию 1) на один плейлист: многие провайдеры разрешают одно подключение на аккаунт, и параллельная проверка выбила бы телевизор.

Запуск: `mih health-check` (по cron или таймеру) или `POST /api/v1/streams/check`. Сводка: `GET /api/v1/streams/health`, история потока: `GET /api/v1/streams/{id}/health`.

## Пока не сделано

- приоритет избранного и недавно смотревшихся (нет таблиц избранного);
- ffprobe для DASH и проверки кодеков;
- встроенный планировщик внутри `mih serve`;
- закрепление проверенного IP-адреса между проверкой и подключением (DNS rebinding), как и у загрузки плейлистов.
