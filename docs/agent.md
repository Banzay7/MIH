# Инструкция для домашнего агента

Для агента, который включает каналы на телевизоре: AI-агент, Home Assistant, скрипт или голосовой помощник. Описано, что агент берёт у MIRTVONLINE, где это хранит, как запускает канал и что сообщает обратно. Ответы агента о запуске нужны для качества списков: телевизор дома видит поток точнее, чем сервер.

Ниже `<сервер>` — адрес MIRTVONLINE, `<токен>` — `MIH_API_TOKEN`. Запросы к `/api/v1/...` идут с заголовком `Authorization: Bearer <токен>`.

## MCP-сервер

Самый быстрый путь для AI-агента: MCP-сервер с девятью инструментами. Ответы короткие (JSON без пробелов, короткие поля, пустые поля опущены, не больше 50 строк, остаток в `more`), запросы идут прямо в SQLite, индекс имён каналов держится в памяти и пересобирается сам, когда меняется каталог.

**Подключение.** Сервер включается переменной `MIH_MCP_PORT` и слушает `MIH_MCP_HOST` (по умолчанию `127.0.0.1`). На другом адресе он без токена не запустится. Токен `MIH_MCP_TOKEN`, если пуст, то `MIH_API_TOKEN`. Транспорты:

- HTTP: `POST http://127.0.0.1:<порт>/mcp` (Streamable HTTP, без сессий и потоков: каждый запрос получает один JSON-ответ), заголовок `Authorization: Bearer <токен>`. Запрос из браузера с чужим `Origin` отклоняется.
- stdio: `mih mcp` (в Docker: `docker exec -i <контейнер> mih mcp`). Сети нет вообще.

На тестовом стенде порт MCP опубликован только на loopback хоста ([deploy/vps-test](../deploy/vps-test/README.md#mcp-для-агента-на-этом-же-сервере)).

**Инструменты.**

| Инструмент | Что делает | Пример ответа |
|---|---|---|
| `channels(q, limit=5)` | канал по имени, как его говорят: «первый», «россия 24», `rossiya24`; сначала те, что играют | `{"items":[{"id":"ch_…","name":"Первый канал HD","lvl":"ok","now":"Новости","till":"19:30","next":"Футбол","at":"19:30"}]}` |
| `search(q, limit=10, all=false)` | передачи в программе, свободный текст со временем: «футбол сегодня вечером» | `{"items":[{"title":"Футбол…","ch":"Матч ТВ","cid":"ch_…","at":"21:00","end":"23:00","more":2}],"tz":"Europe/Berlin"}` |
| `now(ids?, list?, limit=20)` | что идёт сейчас и далее: по id, по списку или на всех играющих каналах | `{"items":[{"id":…,"name":…,"now":…,"till":…}],"more":120}` |
| `schedule(id, day="today", hours=6)` | программа канала: `today` (с текущего момента), `tomorrow` или ISO-время | `{"items":[{"at":"19:30","title":"…"}]}` |
| `play(id)` | до трёх потоков, лучший первым, с `ua`/`ref`, если нужны плееру | `{"streams":[{"stream_id":"st_…","url":"…","lvl":"ok"}]}` |
| `report(stream_id, ok, ms?, error?, cmd?)` | поток **не** заиграл (`ok=false`); об успехе сообщать не нужно, молчание значит «играет». С `cmd` — ответ на команду из `queue` | `{"stream_id":"st_…","status":"active"}` |
| `queue(wait=0)` | команды кнопки «На ТВ» из веб-интерфейса, каждая выдаётся один раз; `wait` до 50 с ждёт новую (long poll) | `{"items":[{"cmd":"…","id":"ch_…","name":"Первый канал HD","streams":[…]}]}` |
| `topics(add?, remove?, hours=24)` | темы для уведомлений и что по ним скоро | `{"topics":["футбол"],"soon":[…]}` |
| `status()` | сколько каналов играет, списки, когда обновлялись данные | |

`lvl`: `ok` (играл за 48 часов), `doubtful`, `unknown` (не проверялся), `dead`. Время местное (`MIH_TIMEZONE`, поле `tz`): `19:30` сегодня, `10-28 07:00` в другой день.

Типичный сценарий «включи Первый»: `channels("первый")` → `play(id)` → запуск первого потока; не заиграл → `report(stream_id, ok=false)` и следующий поток. Для «что посмотреть вечером»: `search("фильм вечером")` или `now()`.

**Кнопка «На ТВ».** Включает ТВ агент (`MIH_PLAYBACK=agent`, по умолчанию). Нажатие ставит команду в очередь; агент забирает её через `queue` (опрос или `wait`) вместе с тремя потоками и запускает первый своим способом. Сообщать нужно только о неудаче: `report(stream_id, ok=false, cmd=…)`, потом следующий поток. Ошибку плеера сообщайте сразу, а «всё ещё грузится» только через 30 секунд, с `error="timeout"`: HD-потоки иногда стартуют по 20 секунд. Последний поток не выключайте. Молчание 100 секунд после выдачи значит «играет»: первый поток без неудачи засчитывается как запуск на ТВ (как `started` ниже). Если не заиграл ни один выданный поток, команда сразу завершается ошибкой, и веб-интерфейс это показывает. Исключение: последний поток только не успел загрузиться (`timeout`). ТВ его ещё грузит, поэтому команда считается запущенной без подтверждения, и интерфейс пишет «канал грузится дольше обычного». Команду, которую никто не взял за 30 секунд, интерфейс показывает как «агент не взял» (`no_agent`). Если агент умеет принимать вебхуки, укажите `MIH_AGENT_WEBHOOK` (и `MIH_AGENT_WEBHOOK_TOKEN`): сервер отправит туда `{"event":"play","command_id":…,"channel_id":…,"channel":…}` сразу после нажатия, и опрашивать не нужно.

**Лимит.** `MIH_MCP_DAILY_LIMIT` ограничивает число вызовов инструментов за сутки (UTC), `0` — без лимита. Для своей установки лимит не нужен; он для будущего общего сервера.

Ниже описан тот же обмен через файлы и REST API, для агентов без MCP.

## 1. Что забирать и где хранить

| Что | Откуда | Как часто | Где хранить у агента |
|---|---|---|---|
| Весь каталог: каналы, их другие имена, ключи для голоса, потоки с заголовками, что идёт сейчас | `GET <сервер>/lists/catalog.jsonl?token=<токен>` | раз в сутки и после ошибки запуска | локальный файл `catalog.jsonl` рядом с конфигурацией агента, права только для агента: в нём адреса потоков |
| Готовый плейлист для плеера (если плеер сам читает M3U) | `GET <сервер>/lists/<имя>.m3u?token=<токен>` | плеер обновляет сам | в настройках плеера, не копировать |
| Телепрограмма к плейлисту | `GET <сервер>/lists/<имя>.xml.gz?token=<токен>` | плеер обновляет сам | в настройках плеера |
| Что идёт сейчас и поиск передач («что посмотреть вечером») | `GET /api/v1/now`, `POST /api/v1/search` | по запросу пользователя | не хранить |

Файл каталога пересобирается после каждой фоновой задачи. Чаще раза в сутки скачивать его незачем. Поля описаны в [lists.md](lists.md#каталог-целиком).

`catalog.jsonl` и `.m3u` в облако или в публичные папки не кладите: в ссылках бывают токены провайдеров.

## 2. Как найти канал по фразе

1. Привести фразу к ключу, как это делает `compact()` из `mih.identity.search_keys`: нижний регистр, `ё` → `е`, оставить только буквы и цифры. Пример: «Россия 24» → `россия24`.
2. Найти канал, у которого ключ есть в `search_keys[]`. Там же латиница и народные имена (`rossiya24`, `ртр`, `первый`).
3. Не нашлось: искать по вхождению в `name` и `aliases[]`, потом спросить пользователя.

## 3. Как запустить

- Потоки в `streams[]` уже отсортированы: **лучший первым**. Берите первый с `level: "ok"`, при неудаче следующий.
- Нет потока с `level: "ok"`, но есть поток с `reason: "geo"`: с сервера он не открылся из-за геоблока, а дома может заиграть. Пробуйте его и обязательно отправьте отчёт (раздел 4), тогда сервер начнёт считать его рабочим.
- Если `requires_headers: true`, передайте плееру `headers.user_agent` и `headers.referer`. Иначе будет HTTP 403.
- Плеер, который не умеет заголовки или сам выбирает поток: отдайте ему `<сервер>/play/<channel_id>.m3u?token=<токен>`. Это маленький плейлист с тремя лучшими потоками и нужными заголовками.

## 4. Что сообщать обратно

После каждого запуска, когда пошла картинка или прошло 30 секунд, отправьте результат:

```
POST /api/v1/streams/<stream_id>/playback
{"result": "started", "startup_ms": 2300}
```

или при неудаче:

```
POST /api/v1/streams/<stream_id>/playback
{"result": "failed", "error": "timeout"}
```

- **`started`**: плеер перешёл в состояние воспроизведения (в Home Assistant `media_player` в `playing`), картинка идёт. `startup_ms` — сколько прошло от команды до начала, если известно.
- **`failed`**: плеер показал ошибку или чёрный экран (сообщайте сразу), либо за 30 секунд так и не заиграло (`timeout`). В `error` коротко причина: `timeout`, `http_403`, `player_error`, `no_video`.
- `stream_id` берите из того потока, который реально запускали. При переходе к запасному потоку отправьте отчёт по каждому.

Что сервер делает с отчётом:
- `started` сразу делает поток рабочим, даже если сервер его не видит (например, из-за геоблока). 72 часа неудачи проверки сервера по нему не засчитываются.
- `failed` с ошибкой плеера помечает поток сомнительным и ставит его на проверку сервером в ближайшие 10 минут, не дожидаясь еженедельной. 72 часа удачные проверки сервера этого не отменяют: ТВ видит поток так, как его видит зритель.
- `failed` с `timeout` (медленный старт) потоку не засчитывается ни в плюс, ни в минус: медленный и мёртвый поток со стороны ТВ выглядят одинаково. Сервер сразу проверяет поток сам, и решает его проверка: открылся, и поток остаётся рабочим; нет, и это обычная неудача.

## 5. Чего агент не делает

- Не проверяет каналы сам по расписанию: это работа сервера. Агент сообщает только о настоящих запусках.
- Не меняет списки и источники через API без просьбы пользователя.
- Не пересылает адреса потоков в чаты и облака.
