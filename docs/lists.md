# Валидные списки каналов

Код: `src/mih/lists.py`, команда `mih list`.

## Когда канал валиден

Канал попадает в список, если у него есть хотя бы один поток, который недавно реально запускался. Уровень потока:

| Уровень | Когда |
|---|---|
| `ok` | проверка сервера или запуск на устройстве прошли за последние 10 дней, и после этого сбоев не было (рабочий поток проверяется раз в неделю) |
| `doubtful` | работал за последние 14 дней, но сейчас сбоит, или последний успех старше 10 дней, или устройство после успеха не смогло его запустить |
| `unknown` | ещё ни разу не проверялся |
| `dead` | ни разу не заработал, не работает дольше 14 дней, в карантине, пропал из плейлиста, нужен DRM или логин |

Уровень фида равен уровню его лучшего потока, уровень канала равен уровню лучшего фида. По умолчанию в список идут только `ok`; `--level doubtful` добавляет сомнительные, `--level unknown` ещё и непроверенные.

На каждый фид в плейлисте одна запись с лучшим потоком. Копии со сдвигом времени (`+2`, `+4`) по умолчанию не включаются (`--timeshift`), каналы 18+ тоже (`--adult`).

## Геоблок

Сервер вне страны канала часто получает HTTP 403 или не получает ответа. Это считается обычным сбоем: зритель тоже обычно вне этой страны, и поток, который не открывается на сервере, скорее всего не заиграет и дома. Если устройство сообщило об успешном запуске (`POST /api/v1/streams/{id}/playback`), поток становится `ok` независимо от проверки сервера.

## Фильтры

| Параметр | Что делает |
|---|---|
| `--country RU` | страна канала: из `tvg-country` и из суффикса id iptv-org (`Perviykanal.ru` → RU); можно повторять |
| `--lang ru` | язык из `tvg-language`; названия (`Russian`, `русский`) приводятся к кодам |
| `--category news` | категория из `mih export` (news, sport, kids, movies...); можно повторять |
| `--epg-only` | только каналы с программой передач |
| `--epg-url URL` | адрес программы для заголовка плейлиста (`url-tvg`) |

## Что получается

- `<имя>.m3u`: плейлист для плеера, содержит ссылки на потоки;
- `<имя>.xml.gz`: программа передач именно этого списка (XMLTV, gzip): все каналы списка из всех подключённых гидов, за сутки назад и всё, что известно вперёд. `tvg-id` в плейлисте совпадает с id канала в этом файле, поэтому плеер сопоставляет их без угадывания по названию. Копия `+2` без своего гида получает программу основного канала со сдвигом;
- `<имя>.json`: каналы списка с уровнем и датой последнего успеха, `guide` (есть ли у канала передачи в `<имя>.xml.gz`) и `with_guide` (сколько таких каналов), а также `excluded`: каналы, подходящие под фильтр, но не попавшие в список, с причиной;
- `<имя>.csv`: каналы списка для таблицы.

Причины в отчёте: `geo_suspect` (последняя ошибка 403 или 451, вероятно блокировка по стране), `no_answer` (таймаут, нет соединения), `gone` (404, 410, домен не существует), `unchecked`, `never_worked`, `failing`, `stale`, `device_failed`, `drm`, `login`, `absent`, `no_stream`.

## Готовые списки и ссылка для плеера

Набор списков задаётся JSON-файлом в `MIH_LISTS_FILE`:

```json
{
  "ru": {"country": ["RU"]},
  "ru-news": {"country": ["RU"], "category": ["news"], "epg_url": "https://example.org/epg.xml.gz"},
  "kids": {"lang": ["ru"], "category": ["kids"], "level": "doubtful"}
}
```

Ключи: `country`, `lang`, `category`, `exclude_category`, `level`, `timeshift`, `adult`, `epg_only`, `epg_url`, те же, что у `mih list`. Без файла собирается один список `valid`: все каналы, которые играют.

Списки пересобираются после каждой проверки потоков (задача `health` планировщика) в `<MIH_EXPORT_DIR>/lists/`. Вручную: `mih list --presets`.

Ссылка для плеера: `http://<сервер>/lists/<имя>.m3u?token=<MIH_API_TOKEN>` (токен в адресе, потому что плееры не умеют передавать заголовки). Программа: `http://<сервер>/lists/<имя>.xml.gz?token=<MIH_API_TOKEN>`. Если задан `MIH_PUBLIC_URL`, этот адрес сам вписывается в заголовок плейлиста (`url-tvg`), и плееру достаточно одной ссылки; `epg_url` в описании списка его заменяет. Там же `<имя>.json` и `<имя>.csv`. Перечень списков с числом каналов, числом каналов с программой и причинами исключения: `GET /api/v1/lists`.

Файл программы переписывается после каждого обновления гидов (задача `epg`), а между ними не чаще раза в 30 минут при смене состава списка и раз в 6 часов в остальное время: проверки потоков пересобирают списки каждые 10 минут, а программа меняется два раза в сутки.

## Откуда программа и что хранится

- Гид, который назван в самом плейлисте (`url-tvg` или `x-tvg-url` в строке `#EXTM3U`), добавляется как источник программы автоматически, с приоритетом выше публичных гидов, и загружается при ближайшем запуске задачи `epg`.
- Канал гида сопоставляется с каналом каталога по порядку: `tvg-id` фида; то же название с тем же регионом и сдвигом; затем на уровне канала: id без части после `@`, связь, записанная при прошлом импорте, название, альтернативное название из справочника iptv-org (`НТВ` для `NTV (Russia)`), и последним транслитерация (`Пятница` = `Pyatnitsa`). Фид выбирается по сдвигу и региону; если у канала один региональный фид, например `(Russia)`, берётся он. Несколько кандидатов: решает человек (`needs_review`). Правило видно в `GET /api/v1/epg/channels`.
- Если гиды с более высоким приоритетом не содержат передач для фида, используется тот, у которого они есть.
- При `MIH_EPG_SCOPE=tracked` (по умолчанию) полная программа хранится только для каналов из готовых списков и избранных каналов; для остальных только передачи по отслеживаемым темам и избранные передачи. Прошедшие передачи хранятся `MIH_EPG_RETENTION_DAYS` дней (3).

### Покрытие и автопилот гидов

После каждого обновления программы (задача `epg`) сервис считает, у скольких **рабочих** каналов (поток уровня `ok`) есть программа, по странам. Страна берётся из `tvg-country`, справочника или суффикса `tvg-id`; если её нет, из языка канала (`ru` → RU, `de` → DE). Канал считается с программой, если его фид сопоставлен с каналом включённого гида, в котором есть передачи.

Автопилот (`MIH_EPG_AUTO`, по умолчанию включён) подбирает гиды сам:

1. Берёт страны, где у рабочих каналов нет программы хотя бы у 3 каналов, начиная с той, где таких больше всего.
2. Для каждой добавляет на пробу следующий известный публичный гид этой страны (`src/mih/epg/known.py`: сначала гиды, сделанные для страны, затем файлы epgshare01 и epg.pw). Одна страна — один гид на пробе, до 3 новых гидов за запуск. После добавления задача `epg` запускается снова через 5 минут.
3. На следующем запуске оценивает: если гид дал программу хотя бы одному рабочему каналу, у которого её больше ни откуда нет, гид остаётся (приоритет 120, ниже ручных и `url-tvg`). Иначе удаляется вместе со всем, что сохранил, и пробуется следующий. Гид, который не скачался или не прочитался за 2 дня, тоже удаляется.
4. Убранный гид снова пробуется через 30 дней: публичные гиды появляются и пропадают.

Гид на пробе только сопоставляется с каталогом: каналы из него, которых нет в плейлистах, в каталог не добавляются. Что сохраняется из его программы, по-прежнему решает `MIH_EPG_SCOPE`.

Итог в событии задачи («рабочих каналов с программой: N из M», какие гиды на пробе, оставлены, убраны), подробно `GET /api/v1/epg/coverage` или `mih epg-coverage`: по каждой стране число рабочих каналов, сколько с программой и примеры каналов без неё, плюс история проб. Ответ хранится 10 минут.

## Вкладка «Покрытие»

Вкладка **Покрытие** веб-интерфейса показывает весь каталог в графиках: сколько каналов всего, у скольких есть ссылка на поток, сколько живых и сколько живых с программой; то же по странам (с сортировкой по нехватке программы); рост по дням; что нашёл грабер плейлистов и сколько упаковал; новые потоки по дням; потоки по источникам; почему каналы не попали в живые.

Цифры считаются в фоне, а не при открытии вкладки: после задачи с программой сразу, после проверки потоков, упаковщика и обновления плейлистов не чаще раза в 30 минут. Результат лежит в `<данные>/report.json` вместе с одной точкой на день за 3 месяца (для графика роста). API: `GET /api/v1/report`. Пересчитать сейчас: `mih report`.

## Весь каталог одним файлом

Вместе со списками в ту же папку пишутся `catalog.jsonl` и `catalog.csv`. Это всё сразу: каждый канал каталога и каждый его поток, без фильтров (каналы 18+ и копии со сдвигом тоже, со своими полями). В них есть ссылки на потоки, поэтому права у файлов 0640 и в выгрузку на Google Drive они не идут.

`catalog.jsonl`: один канал на строку, потоки внутри, лучший первым.

| Поле | Что это |
|---|---|
| `channel_id`, `name`, `aliases[]`, `tvg_ids[]` | канал и его другие названия |
| `search_keys[]` | ключи для поиска голосом: без регистра, дефисов и пробелов, латиницей, без слова «канал», народные имена (`россия24`, `rossiya24`, `russia24`, `ртр`, `первый`). Искать по `compact(запрос)` из `mih.identity.search_keys`: нижний регистр, ё→е, только буквы и цифры |
| `country`, `countries[]`, `languages[]`, `categories[]`, `logo_url` | метаданные |
| `level`, `reason`, `last_error`, `last_ok_at` | уровень канала (по лучшему потоку) и почему он ниже `ok` |
| `lists[]` | в какие готовые списки канал попал |
| `epg_available`, `now{title,start,stop}`, `next{title,start}` | программа на момент сборки файла (он пересобирается после каждой задачи) |
| `streams[]` | потоки: `stream_id`, `feed_id`, `region`, `timeshift_min`, `quality`, `format`, `source`, `level`, `reason`, `last_error`, `last_ok_at`, `home_ok_at`, `url`, `headers{user_agent, referer}`, `requires_headers` |

`requires_headers: true` значит, что поток открывается только с этими заголовками: плеер, который не умеет их передать, получит HTTP 403.

`catalog.csv`: то же для чтения глазами, одна строка на поток (канал без потоков одной строкой).

Ссылка: `http://<сервер>/lists/catalog.jsonl?token=<MIH_API_TOKEN>`. Имя `catalog` занято, готовый список так назвать нельзя.

## Отчёт о запуске дома

Проверка с сервера вне страны канала часто получает 403 или таймаут. Поэтому решающий голос у телевизора: после включения отправьте `POST /api/v1/streams/{stream_id}/playback` с `{"result": "started"}` или `{"result": "failed"}`. Успешный запуск сразу делает поток `ok` (даже из карантина) и в течение `MIH_HEALTH_DEVICE_TRUST_HOURS` (72 часа) неудачи проверки сервера по нему не засчитываются. Время последнего успешного запуска видно в `home_ok_at`.
