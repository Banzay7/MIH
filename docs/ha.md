# Home Assistant: «На ТВ» напрямую

Кнопка «На ТВ» может идти прямо в Home Assistant, без агента: сервер MIRTVONLINE вызывает ваш скрипт HA через REST API и передаёт ему адреса потоков и название канала. Как включить канал на телевизоре, решает сам скрипт. MIRTVONLINE ничего не меняет в настройках Home Assistant.

## Что нужно

1. **Связь сервера с Home Assistant.** Сервер должен открывать адрес HA, например `http://homeassistant.local:8123` в той же сети, адрес HA в Tailscale (`http://100.x.y.z:8123`) или внешний адрес Nabu Casa. Проверка с сервера: `curl -s -o /dev/null -w '%{http_code}\n' <адрес>/api/` отвечает `401` (адрес доступен, токена ещё нет).
2. **Долгоживущий токен HA.** В Home Assistant: нажмите своё имя внизу слева → вкладка **Security** (Безопасность) → **Long-lived access tokens** (Долгосрочные токены доступа) → **Create token** (Создать токен) → введите имя, например `mirtvonline` → **OK** → скопируйте токен (он показывается один раз). Токен вписывается только в `.env` на сервере, его не нужно пересылать в чат или класть в git.
3. **Скрипт в HA**, который включает канал. Свой готовый скрипт подходит: укажите его имя в `MIH_HA_SCRIPT`. Для Android TV и Google TV есть готовый пример через Companion: [examples/ha/mih_play.yaml](examples/ha/mih_play.yaml) (ниже раздел «Android TV и Google TV через Companion»).

## Настройки

| Переменная | По умолчанию | Что это |
|---|---|---|
| `MIH_HA_URL` | нет | Адрес Home Assistant, без `/` в конце |
| `MIH_HA_TOKEN` | нет | Долгоживущий токен HA |
| `MIH_HA_SCRIPT` | `mih_play` | Скрипт, который запускается (`script.` в начале можно не писать) |
| `MIH_HA_STREAMS` | `3` | Сколько адресов потоков передавать в `urls` |
| `MIH_HA_FIELDS` | нет | Переименование переменных под ваш скрипт: `channel=name,url=stream_url`; `stream_id=` (пусто) не передаёт переменную |
| `MIH_HA_TIMEOUT_S` | `60` | Сколько ждать, пока скрипт отработает |
| `MIH_HA_NOTIFY` | нет | Сервис уведомлений Companion на ТВ, `notify.mobile_app_<device>`: проверка связи убеждается, что он есть в HA, а скрипт получает его в `notify_service` |
| `MIH_PLAYBACK` | `agent` | `ha` делает HA способом по умолчанию для всех браузеров. Безопасное значение `agent`: HA выбирают в настройках браузера после успешной проверки |

Без `MIH_HA_URL` и `MIH_HA_TOKEN` мост выключен, и веб-интерфейс его не предлагает.

## Переменные, которые получает скрипт

| Переменная | Значение |
|---|---|
| `url` | Лучший поток канала (тот, что работал последним; потоки, которым нужны особые заголовки, идут в конце) |
| `urls` | До `MIH_HA_STREAMS` потоков, лучший первым: запасные, если первый не заиграет |
| `channel` | Название канала |
| `channel_id` | ID канала в MIRTVONLINE |
| `stream_id`, `command_id` | ID потока и команды, для журнала |
| `notify_service` | Значение `MIH_HA_NOTIFY`, если задано |
| `play_url` | Подписанная ссылка `MIH_PUBLIC_URL/play/<канал>`, которая сама выберет живой поток; только если задан `MIH_PUBLIC_URL` |

Пример скрипта для медиаплеера, который умеет открывать адрес (`scripts.yaml`):

```yaml
mih_play:
  alias: MIRTVONLINE play
  fields:
    url: {description: Stream URL}
    channel: {description: Channel name}
  sequence:
    - action: media_player.play_media
      target:
        entity_id: media_player.living_room_tv
      data:
        media_content_id: "{{ url }}"
        media_content_type: url
```

Сервер вызывает скрипт напрямую (`POST /api/services/script/<имя>?return_response`) и ждёт, пока он закончится: скрипт отработал — команда `started`, интерфейс пишет «Home Assistant выполнил скрипт». Скрипт может сам сообщить результат: последний шаг `stop: … response_variable: result` с `result: {ok: false, error: "…"}` даёт ошибку `ha_not_playing`, и интерфейс показывает текст `error`. Ошибки: `ha_notify_missing` (в HA нет сервиса уведомлений Companion, который зовёт скрипт: см. ниже), `ha_unreachable` (нет связи), `ha_unauthorized` (токен не принят), `ha_script_not_found` (нет такого скрипта), `ha_script_failed` (скрипт упал, подробности в журнале HA), `ha_timeout` (не ответил за `MIH_HA_TIMEOUT_S`; канал, возможно, всё же включится). Адреса потоков уходят только в HA и в ответ браузеру не попадают. Текст ошибки от HA интерфейс показывает, но сервер сначала убирает из него адреса, IP и токены.

В ответе команды есть `stages`: время каждого шага в UTC с миллисекундами (`accepted`, `ha_called`, `ha_finished`, `started` или `failed`). По ним видно, где ушло время: на сервере, в HA или на ТВ. Адресов и токенов там нет.

## Android TV и Google TV через Companion

Рабочий способ для Android TV и Google TV: приложение **Home Assistant Companion** на телевизоре. Скрипт отправляет ему команды через сервис уведомлений `notify.mobile_app_<device>`: `command_activity` открывает поток в плеере, `command_media` нажимает «Play». ADB не нужен: ни отладка по сети на ТВ, ни открытые на нём порты.

Готовый скрипт: [examples/ha/mih_play.yaml](examples/ha/mih_play.yaml). В нём замените `<device>` на имя вашего ТВ в Home Assistant, а на сервере задайте `MIH_HA_SCRIPT=mih_play` и `MIH_HA_NOTIFY=notify.mobile_app_<device>`.

**Сервис уведомлений у каждой установки свой.** Его имя берётся из имени устройства при входе в Companion. Не переносите чужое имя из примеров и не зашивайте его в скрипт: скрипт берёт его из `notify_service`. После повторного входа или перерегистрации Companion имя может измениться, а старый сервис пропадает. Тогда HA принимает команду, но ТВ ничего не делает. Как проверить:

1. В Home Assistant: **Developer tools** (Инструменты разработчика) → вкладка **Actions** (Действия) → в поле действия начните вводить `notify.mobile_app_` — список покажет актуальное имя.
2. Если имя изменилось, впишите новое в `MIH_HA_NOTIFY` на сервере (и в свои автоматизации, если они его используют) и перезапустите сервер.
3. В веб-интерфейсе: **Настройки** → **Кнопка «На ТВ»** → **Проверить связь с HA**. С `MIH_HA_NOTIFY` проверка ищет этот сервис в HA и пишет `ha_notify_missing`, если его нет. Если скрипт зовёт пропавший сервис, команда тоже завершается ошибкой `ha_notify_missing`, а не ложным «Запущено».

**Ждать плеер, а не фиксированное время.** Длинные `delay` на 10–15 секунд делают каждый запуск медленным. Пример ждёт, пока плеер действительно окажется на экране (датчик Companion **Last used app**, `sensor.<device>_last_used_app`; включите его в Companion → **Manage sensors** (Управление датчиками)), не дольше 8 секунд и с одной повторной попыткой, затем отправляет «Play» и ждёт ещё 1 секунду. Если плеер так и не открылся, скрипт отвечает `{ok: false, error: "player did not open"}`, и команда получает `ha_not_playing`. На тестовом стенде запуск так занимает около 3 секунд вместо 11.

Название канала в ответе скрипта удобно сравнивать без хвостов в скобках: `Название (1080p)` и `Название [HD]` — тот же канал.

Для IPTV телевизору лучше кабель или Wi‑Fi 5 ГГц, а не 2,4 ГГц: картинка стабильнее. Это настройка сети, MIRTVONLINE её не меняет.

## В веб-интерфейсе

**Настройки** → блок **Кнопка «На ТВ»**: выберите «Напрямую через Home Assistant». Выбор хранится в браузере, так что телефон может идти через HA, а другой браузер через агента. При открытии настроек сервер сразу проверяет HA и пишет результат рядом с кнопкой **Проверить связь с HA**: адрес и токен, наличие скрипта и, если задан `MIH_HA_NOTIFY`, сервиса Companion. Проверка ничего не запускает.

API: `POST /api/v1/playback/commands` с `"adapter": "ha"` или `"agent"`; `GET /api/v1/playback/adapters` — что доступно; `POST /api/v1/playback/ha/check` — проверка связи.

## Передача с начала (catch-up)

В `POST /api/v1/playback/commands` в `target` можно передать `airing_id` (эфир из программы). Если передача уже идёт или закончилась, сервер строит ссылку архива по атрибутам плейлиста (`catchup`, `catchup-source`, `catchup-days`; режимы `default`, `append`, `shift`, `flussonic`) и передаёт скрипту `catchup_url`, `start_ts` (UTC ISO) и `program`. Скрипт HA играет `catchup_url`, если он есть, иначе обычный `url`. Если у источника нет правила архива, канал играет вживую, а команда получает `detail: live_no_catchup`. Передача, которая ещё не началась, запускается как обычный канал.
