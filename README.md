# MIRTVONLINE

Self-hosted каталог и поиск ТВ-каналов и передач с запуском на ТВ через Home Assistant. Внутреннее имя проекта и кода — MIH (Media Intelligence Hub).

MIRTVONLINE не поставляет каналы: он работает только с плейлистами и EPG, которые добавил пользователь.

- Спецификация: [docs/spec/MIH_SPEC_v0.3.md](docs/spec/MIH_SPEC_v0.3.md)
- Лицензия открытой части: [AGPL-3.0](LICENSE). Pro-модули будут распространяться под отдельной коммерческой лицензией.

## Что уже работает

Ранняя стадия (этап E1 спецификации). Сейчас есть ядро каталога:

- импорт M3U из файла или по URL, с сохранением снапшотов;
- объединение дублей из разных плейлистов в один канал, при этом версии `+2` и региональные версии остаются отдельными фидами;
- защита каталога: пустой, битый или подозрительно короткий плейлист не заменяет текущий каталог;
- REST API с токеном; ссылки на потоки не возвращаются ни в одном ответе;
- EPG: импорт XMLTV (`.xml` и `.xml.gz`) из файла или по URL, время в UTC с сохранением исходного, повторы как отдельные эфиры, отмена и версии эфиров при правках сетки;
- привязка программы к фидам по `tvg-id`, затем по имени с учётом региона и сдвига; спорные случаи ждут решения в очереди, ручное решение не перезаписывается;
- фид `+2` без своей программы показывает программу основного фида со сдвигом;
- «сейчас/далее», расписание канала, карточка передачи и покрытие EPG по каналам;
- проверка живости потоков и их жизненный цикл `unverified → new/active → suspect → quarantine → archived` с автоматическим восстановлением, см. [docs/health.md](docs/health.md).

- поиск по передачам и каналам без AI и без интернета: «что завтра про гуманоидных роботов на русском» разбирается на слова, время и язык; ё/е, регистр и окончания («роботов» находит «роботы») учитываются, у каждого результата есть `why_matched`.

- веб-интерфейс (PWA, на русском, для телефона и компьютера) по адресу сервера `/`: «Сейчас в эфире» с прогрессом и «далее», «Скоро начнётся», поиск с фильтрами по времени, языку и типу, список каналов с фильтрами, карточки канала с расписанием по дням и карточки передачи, избранное. Токен API вводится в «Настройках» и хранится только в браузере;
- избранное на сервере (`/api/v1/profiles/default/favorites`) и команды запуска (`/api/v1/playback/commands`). Кнопка «На ТВ» пока заглушка: сервер выбирает лучший живой поток и отвечает `no_adapter`, на устройство ничего не уходит.

Темы (таксономия) и настоящий запуск на ТВ через Home Assistant — следующие шаги.

## Запуск для разработки

```bash
uv venv && uv pip install -e '.[dev]'
pytest

# импорт плейлиста из файла и счётчики каталога
MIH_DATA_DIR=./data .venv/bin/mih import-file my.m3u --source home
MIH_DATA_DIR=./data .venv/bin/mih import-epg-file guide.xml.gz --source home-epg
MIH_DATA_DIR=./data .venv/bin/mih search "новости завтра вечером" --tz Europe/Moscow
MIH_DATA_DIR=./data .venv/bin/mih stats
# проверить потоки, которым пора (удобно запускать по cron/systemd-таймеру)
MIH_DATA_DIR=./data .venv/bin/mih health-check

# API на localhost (без токена разрешено только на 127.0.0.1)
MIH_DATA_DIR=./data .venv/bin/mih serve
# веб-интерфейс: http://127.0.0.1:8765/
# документация API: http://127.0.0.1:8765/api/docs
```

## Docker

```bash
export MIH_API_TOKEN=$(openssl rand -hex 24)
docker compose -f docker-compose.example.yml up -d --build
```

Порт публикуется только на `127.0.0.1`. Для доступа с других устройств поставьте перед сервисом HTTPS-прокси или туннель. Без `MIH_API_TOKEN` контейнер не запустится.

Тестовый стенд на сервере, где уже работают другие сервисы (свои имена, порт, том, лимиты, бэкап и откат): [deploy/vps-test](deploy/vps-test/README.md).

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MIH_DATA_DIR` | `./data` | База SQLite и снапшоты плейлистов |
| `MIH_BIND_HOST` / `MIH_BIND_PORT` | `127.0.0.1` / `8765` | Адрес API |
| `MIH_API_TOKEN` | — | Токен API, не короче 24 символов; обязателен вне localhost |
| `MIH_MAX_DROP_RATIO` | `0.3` | Отклонять снапшот, если записей стало меньше на эту долю |
| `MIH_ALLOW_PRIVATE_SOURCES` | выкл. | `1` разрешает источники в локальной сети |
| `MIH_FETCH_TIMEOUT_S`, `MIH_FETCH_MAX_BYTES` | `30`, 50 МБ | Ограничения загрузки |
| `MIH_EPG_MAX_BYTES` | 256 МБ | Предел распакованного XMLTV |
| `MIH_EPG_RETENTION_DAYS` | `14` | Сколько дней хранить прошедшие эфиры |
| `MIH_TIMEZONE` | `UTC` | Часовой пояс для «сегодня/завтра/вечером» в поиске (IANA, например `Europe/Berlin`) |
| `MIH_HEALTH_VANTAGE` | `server` | Где стоит проверка: `server` (удалённый сервер) или `home` (домашняя сеть) |
| `MIH_HEALTH_CONCURRENCY` | `8` | Сколько потоков проверять одновременно |
| `MIH_HEALTH_PER_SOURCE` | `1` | Одновременных проверок на один плейлист (провайдеры часто дают одно подключение) |
| `MIH_HEALTH_BATCH` | `200` | Сколько потоков проверять за один запуск |
| `MIH_HEALTH_CANARY_URLS` | gstatic, Cloudflare | Адреса проверки собственной сети через пробел; пусто отключает |
