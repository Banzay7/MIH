# MIRTVONLINE

Self-hosted каталог и поиск ТВ-каналов и передач с запуском на ТВ через Home Assistant. Внутреннее имя проекта и кода — MIH (Media Intelligence Hub).

MIRTVONLINE не поставляет каналы: он работает только с плейлистами и EPG, которые добавил пользователь.

- Спецификация: [docs/spec/MIH_SPEC_v0.3.md](docs/spec/MIH_SPEC_v0.3.md)
- Лицензия открытой части: [AGPL-3.0](LICENSE). Pro-модули будут распространяться под отдельной коммерческой лицензией.

## Что уже работает

Ранняя стадия (этап E1 спецификации). Сейчас есть ядро каталога:

- импорт M3U из файла или по URL, с сохранением снапшотов;
- объединение дублей из разных плейлистов в один канал, при этом версии `+2` и региональные версии остаются отдельными фидами;
- защита каталога: пустой, битый или подозрительно короткий плейлист не заменяет текущий каталог;
- REST API с токеном; ссылки на потоки не возвращаются ни в одном ответе;
- EPG: импорт XMLTV (`.xml` и `.xml.gz`) из файла или по URL, время в UTC с сохранением исходного, повторы как отдельные эфиры, отмена и версии эфиров при правках сетки;
- привязка программы к фидам по `tvg-id`, затем по имени с учётом региона и сдвига; спорные случаи ждут решения в очереди, ручное решение не перезаписывается;
- фид `+2` без своей программы показывает программу основного фида со сдвигом;
- «сейчас/далее», расписание канала, карточка передачи и покрытие EPG по каналам;
- проверка живости потоков и их жизненный цикл `unverified → new/active → suspect → quarantine → archived` с автоматическим восстановлением, см. [docs/health.md](docs/health.md).

- поиск по передачам и каналам без AI и без интернета: «что завтра про гуманоидных роботов на русском» разбирается на слова, время и язык; ё/е, регистр и окончания («роботов» находит «роботы») учитываются, у каждого результата есть `why_matched`.

- веб-интерфейс (PWA, на русском, для телефона и компьютера) по адресу сервера `/`: «Сейчас в эфире» с прогрессом и «далее», «Скоро начнётся», поиск с фильтрами по времени, языку и типу, список каналов с фильтрами, карточки канала с расписанием по дням и карточки передачи, избранное. Токен API вводится в «Настройках» и хранится только в браузере;
- избранное на сервере (`/api/v1/profiles/default/favorites`) и команды запуска (`/api/v1/playback/commands`). Кнопку «На ТВ» выполняет домашний агент: команда ждёт его в MCP-инструменте `queue` ([docs/agent.md](docs/agent.md#mcp-сервер)), или напрямую скрипт Home Assistant ([docs/ha.md](docs/ha.md)); `MIH_PLAYBACK=off` только выбирает поток и отвечает `no_adapter`.

- выгрузка каталога в папку (`mih export`): `channels.json` (все каналы с категориями, исходными группами плейлистов, странами, языками, источниками, состоянием потоков `ok/grey/down` и наличием EPG, без ссылок на потоки), `channels.csv` (то же для таблицы) и `playlist.m3u` (по одному лучшему живому потоку на фид, сгруппированный по категориям, для любого плеера). `playlist.m3u` содержит ссылки на потоки и создаётся с правами `640`; `--no-playlist` его не пишет. Категории берутся из `group-title` плейлистов, затем из названия канала, затем из категорий передач в EPG (ru/en/vi).
- валидные списки каналов (`mih list`): только каналы, которые сейчас играют, с фильтрами по стране, языку и категории; файлы `<имя>.m3u`, `.csv`, `.json` и отчёт, почему канал не попал; плюс `catalog.jsonl` и `catalog.csv`: весь каталог в одном файле со ссылками, `stream_id`, заголовками и тем, что идёт сейчас. Правила в [docs/lists.md](docs/lists.md).
- справочник каналов iptv-org (`mih import-directory`): страна, языки и категории для каналов каталога, склейка дублей по `tvg-id` и названиям, по желанию каналы страны без потоков (`--country RU`). Подробно в [docs/directory.md](docs/directory.md).

- инструкция для домашнего агента (Hermes, Home Assistant, скрипт): что забирать, как найти и запустить канал, как сообщить, заиграл ли он. См. [docs/agent.md](docs/agent.md).
- грабер плейлистов: сам находит публичные плейлисты (сиды, поиск по GitHub, страницы и Telegram), выборочно проверяет их и понемногу добавляет в каталог только рабочие потоки; утечки подписок и DRM отсеиваются. См. [docs/discovery.md](docs/discovery.md).
- выгрузка на Google Диск: `channels.json` и `channels.csv` (каналы с категориями и здоровьем, без ссылок на потоки) сами обновляются в выбранной папке Диска, раз в 6 часов и только если каналы изменились. См. [docs/drive.md](docs/drive.md).
- статус и уведомления: встроенный планировщик `mih serve` обновляет плейлисты и программу по URL, проверяет потоки и раз в день присылает сводку. Экран «Статус» в веб-интерфейсе показывает, что сервис делает сейчас, итог каждой задачи, план на сутки и ленту событий. Важное (ошибки, изменения в каталоге, запуск и остановка) приходит пушем через [ntfy](https://ntfy.sh), повторяющаяся проблема не чаще раза в 6 часов, рутинные запуски попадают только в ленту и сводку. См. [docs/notifications.md](docs/notifications.md).

Темы (таксономия) и настоящий запуск на ТВ через Home Assistant — следующие шаги.

## Запуск для разработки

```bash
uv venv && uv pip install -e '.[dev]'
pytest

# импорт плейлиста из файла и счётчики каталога
MIH_DATA_DIR=./data .venv/bin/mih import-file my.m3u --source home
MIH_DATA_DIR=./data .venv/bin/mih import-epg-file guide.xml.gz --source home-epg
MIH_DATA_DIR=./data .venv/bin/mih search "новости завтра вечером" --tz Europe/Moscow
MIH_DATA_DIR=./data .venv/bin/mih stats
# выгрузка каталога с категориями в папку (по умолчанию MIH_EXPORT_DIR или ./data/export)
MIH_DATA_DIR=./data .venv/bin/mih export --out /path/to/folder
# валидный список: российские новости, только проверенные за 10 дней
MIH_DATA_DIR=./data .venv/bin/mih list --name ru-news --country RU --category news
# проверить потоки, которым пора (удобно запускать по cron/systemd-таймеру)
MIH_DATA_DIR=./data .venv/bin/mih health-check
# что сервис делает и что запланировано; задача по требованию; тестовый пуш
MIH_DATA_DIR=./data .venv/bin/mih status
MIH_DATA_DIR=./data .venv/bin/mih run-job sources   # sources | epg | health | digest
MIH_NTFY_URL=https://ntfy.sh/<ваш-топик> .venv/bin/mih notify-test

# API на localhost (без токена разрешено только на 127.0.0.1)
MIH_DATA_DIR=./data .venv/bin/mih serve
# веб-интерфейс: http://127.0.0.1:8765/
# документация API: http://127.0.0.1:8765/api/docs
```

## Docker

```bash
export MIH_API_TOKEN=$(openssl rand -hex 24)
docker compose -f docker-compose.example.yml up -d --build
```

Порт публикуется только на `127.0.0.1`. Для доступа с других устройств поставьте перед сервисом HTTPS-прокси или туннель. Без `MIH_API_TOKEN` контейнер не запустится.

Тестовый стенд на сервере, где уже работают другие сервисы (свои имена, порт, том, лимиты, бэкап и откат): [deploy/vps-test](deploy/vps-test/README.md).

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MIH_DATA_DIR` | `./data` | База SQLite и снапшоты плейлистов |
| `MIH_BIND_HOST` / `MIH_BIND_PORT` | `127.0.0.1` / `8765` | Адрес API |
| `MIH_API_TOKEN` | — | Токен API, не короче 24 символов; обязателен вне localhost |
| `MIH_MAX_DROP_RATIO` | `0.3` | Отклонять снапшот, если записей стало меньше на эту долю |
| `MIH_ALLOW_PRIVATE_SOURCES` | выкл. | `1` разрешает источники в локальной сети |
| `MIH_FETCH_TIMEOUT_S`, `MIH_FETCH_MAX_BYTES` | `30`, 50 МБ | Ограничения загрузки |
| `MIH_EPG_MAX_BYTES` | 256 МБ | Предел распакованного XMLTV |
| `MIH_EPG_RETENTION_DAYS` | `3` | Сколько дней хранить прошедшие эфиры |
| `MIH_HISTORY_DAYS` | `90` | Сколько дней хранить старые снапшоты плейлистов и гидов (записи в базе и файлы). Последний применённый снапшот источника остаётся всегда |
| `MIH_EPG_SCOPE` | `tracked` | Чью программу сохранять: `tracked` — избранные каналы и каналы готовых списков (`MIH_LISTS_FILE`) целиком, на остальных каналах каталога только передачи по отслеживаемым темам и категориям (`/api/v1/profiles/{id}/topics`) и избранные передачи; пока ничего не отслеживается и списков нет, ведёт себя как `mapped`. `mapped` — все каналы гида, найденные в каталоге. `all` — весь гид |
| `MIH_EXPORT_DIR` | `<MIH_DATA_DIR>/export` | Папка для `mih export` |
| `MIH_LISTS_FILE` | нет | JSON с готовыми списками каналов ([docs/lists.md](docs/lists.md)); без него один список `valid` |
| `MIH_TIMEZONE` | `UTC` | Часовой пояс для «сегодня/завтра/вечером» в поиске (IANA, например `Europe/Berlin`) |
| `MIH_SCHEDULER` | `1` | `0` выключает встроенный планировщик `mih serve`; задачи тогда запускаются только вручную |
| `MIH_EVERY_SOURCES`, `MIH_EVERY_EPG`, `MIH_EVERY_HEALTH` | `6h`, `12h`, `10m` | Как часто обновлять плейлисты и программу по URL и проверять потоки (`30m`, `6h`, `1d`, `off`) |
| `MIH_EVERY_ALERTS`, `MIH_ALERT_LEAD` | `5m`, `15m` | Оповещения по темам: как часто смотреть программу и за сколько до начала присылать пуш; `off` в `MIH_ALERT_LEAD` выключает ([подробнее](docs/notifications.md#оповещения-по-темам)) |
| `MIH_DRIVE_TOKEN`, `MIH_DRIVE_FOLDER_ID`, `MIH_EVERY_DRIVE` | нет, нет, `6h` | Выгрузка каналов на Google Диск ([docs/drive.md](docs/drive.md)); без токена выключена |
| `MIH_MCP_PORT`, `MIH_MCP_HOST`, `MIH_MCP_TOKEN`, `MIH_MCP_DAILY_LIMIT` | нет, `127.0.0.1`, `MIH_API_TOKEN`, `0` | MCP-сервер для AI-агента на своём порту ([docs/agent.md](docs/agent.md#mcp-сервер)); без порта выключен |
| `MIH_PLAYBACK`, `MIH_AGENT_WEBHOOK`, `MIH_AGENT_WEBHOOK_TOKEN` | `agent`, нет, нет | Кто по умолчанию выполняет «На ТВ»: агент через MCP (`queue`), `ha` (скрипт Home Assistant напрямую) или `off`; вебхук будит агента при новой команде |
| `MIH_HA_URL`, `MIH_HA_TOKEN`, `MIH_HA_SCRIPT` | нет, нет, `mih_play` | «На ТВ» напрямую через скрипт Home Assistant, без агента ([docs/ha.md](docs/ha.md)); там же `MIH_HA_STREAMS`, `MIH_HA_FIELDS`, `MIH_HA_TIMEOUT_S` |
| `MIH_EVERY_DISCOVER`, `MIH_EVERY_PACK` | `5m`, `15m` | Грабер плейлистов: поисковик и упаковщик ([docs/discovery.md](docs/discovery.md)); там же `MIH_DISCOVERY_SEARCH_EVERY`, `MIH_GITHUB_TOKEN`, `MIH_DISCOVERY_FILE` и пределы |
| `MIH_ALERT_LINK` | `auto` | Что открывает пуш о передаче: `play` (ссылка `MIH_PUBLIC_URL/play/…`), `stream` (сам адрес потока), `none`; `auto` = `play` при заданном `MIH_PUBLIC_URL`, иначе `stream` |
| `MIH_DIGEST_AT` | `09:00` | Время ежедневной сводки по `MIH_TIMEZONE`; `off` выключает |
| `MIH_NTFY_URL` | — | Адрес топика ntfy (`https://ntfy.sh/<топик>` или свой сервер); пусто = без пушей |
| `MIH_NTFY_TOKEN` | — | Токен доступа ntfy, если топик закрыт |
| `MIH_NOTIFY_LEVEL` | `info` | С какого уровня присылать пуши: `info`, `warning`, `error` |
| `MIH_LANG` | `en` | Язык пушей и ленты событий: `en` или `ru` |
| `MIH_PUBLIC_URL` | — | Адрес веб-интерфейса; тогда нажатие на пуш открывает экран «Статус» |
| `MIH_HEALTH_VANTAGE` | `server` | Где стоит проверка: `server` (удалённый сервер) или `home` (домашняя сеть) |
| `MIH_HEALTH_CONCURRENCY` | `8` | Сколько потоков проверять одновременно |
| `MIH_HEALTH_PER_SOURCE` | `1` | Одновременных проверок на один плейлист (провайдеры часто дают одно подключение) |
| `MIH_HEALTH_BATCH` | `200` | Сколько потоков проверять за один запуск |
| `MIH_HEALTH_DEVICE_TRUST_HOURS` | `72` | Сколько часов отчёт телевизора о запуске важнее проверки сервера |
| `MIH_HEALTH_CANARY_URLS` | gstatic, Cloudflare | Адреса проверки собственной сети через пробел; пусто отключает |
